# 百页行多人合作试玩

主持 v2 的行动协调、持久记忆、版本隔离与完整试玩协议见 [多人主持机制](fiction-multiplayer-host.md)。新旧主持可同时维护各自的存档；部署不自动转换正在进行的旧局。

## 入口与范围

- 书架 `/games/fiction/` 分为单人本和多人本；现有单人 URL、存档及主持规则保持原状。
- 首篇 `/games/fiction/prisoner-13/`，同页提供 20000—20003 四张固定桌。
- 2—6 人是本次轻规则叙事改编的配置，不是原版 D&D 的推荐人数。首次入座为房主，满 2 人可开局，开局后不再接收新成员。
- `/games/fiction/prisoner-13/play/?table=20000` 是同桌共用入口；实际权限来自服务器身份 Cookie，知道桌号不代表可以读取故事或操作角色。
- 本版支持同场协作，每人提交一项连贯行动或明确原地观察，再由房主推进。队内聊天不构成行动授权，房主不能代替其他人提交行动。
- 不包含完整 D&D 数值、掷骰、职业法术系统、分队、私密频道或长篇能力认证。地图合并重复区域并简化连通关系，从伪装厨工抵达码头开始。

## 文件职责

- `functions/_lib/multiplayer/story.js`：服务器端中文场景、核心真相和限制；23 类原作编号区域加撤离节点，地图连接是明确简化后的叙事图。
- `host.js`：独立多人主持与复核指令、结构化候选、状态检查。共用原 `fiction-service.js` 的 `callModel` 和 `fiction-discretion.js` 的体验裁量原则，没有改动单人主持。
- `service.js`、`functions/api/fiction-rooms.js`：身份、桌位、房主顺位、锁、行动声明、聊天、回执和状态持久化。
- `games/fiction/multiplayer.js`、`multiplayer.css`：详情页桌位和多人客户端。
- `games/fiction/assets/prisoner-13.svg`：本次新绘制的主题装饰，不使用官方地图、插画或原书下载。
- `tests/fiction-multiplayer.test.mjs`：身份、并发、人数、权限、幂等、状态和信息隔离验证。

## 状态与权限

匿名玩家身份在服务器生成随机令牌，浏览器仅持有 HttpOnly、Secure、SameSite Cookie，数据库存令牌哈希。显示 ID 不可充当身份凭据，清除 Cookie 后不能只凭名字认领原角色。

每人仅占一桌；房主离桌后按原入座顺序交接。等待桌超过 30 分钟未访问的座位才被释放，已经开局的局不会因短暂离线清空。没有自动剔除进行中的离线角色：其行动仍需本人提交或本人离桌。最后一人离桌或房主明确清桌会先将状态写入多人归档表，再腾出桌位；当前没有从该内部归档恢复游玩的界面。玩家可在清桌前导出带自定义标题的公开故事 Markdown。

共同世界仍采用单一场景位置，物品按角色 ID 归属。每轮必须收齐当前成员声明，移动需全员授权；原地观察者禁止被整体移动。房间锁与持久化回执防止重复结算。聊天使用独立记录，在模型运行时仍可发送，不回写游戏轮次。服务器按成员身份过滤故事，完整世界、主持秘密和模型输入不会下发给玩家；当前多人版不提供完整上下文查看器。

## 上线前验收

2026-09-22：134 项 Node 测试（含 17 项多人测试）、5 项 Python 发布/回退测试通过，Cloudflare Functions 编译通过。隔离副本运行页面生成器，确认保留单人/多人分区、7 张剧本卡和重复生成稳定性。Chrome 桌面 1440×1000 与手机 390×844 双身份完成上桌、人数限制、房主开局、聊天、声明、同步与刷新恢复，未出现页面脚本错误或横向溢出。

本机真实模型共测 3 轮：观察码头、全员同意进入升降笼、一人要求跳往办公室而另一人选择原地观察。第三轮保持在升降笼并提供入口信息，没有替原地观察者移动。耗时约 48、45、55 秒。此证据仅覆盖多人流程及早期互动，不等于本篇通关或长程能力验证；生产发布与线上回读结果另记长期验收目录。

首次生产双人并发验收发现同时提交会短暂碰到 `table_busy`。客户端对明确被拒绝的短写入最多重试 3 次，保留原轮次和请求标识；不自动重试主持调用、网络未知结果或轮次已变化的行动。持续忙碌仍会显示提示。最终线上复测单独保存。
