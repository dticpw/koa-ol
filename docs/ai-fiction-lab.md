# 门后的火光 · 主持裁定试玩

入口：https://koa-ol.com/games/lantern-tomb-lab/ 。本次替换行动核心，不迁移旧存档；原《蛇墓余火》继续使用原规则。

## 目标与架构

解决玩家自由输入被动作白名单拒绝、复合动作被拆回按钮、点火被偷偷改成观察的问题。

1. `fiction-lab-host.js` 根据世界、玩家原话及近期事件提出局部步骤与变化。每轮最多六步，连贯准备、操作、观察可以在一轮完成。
2. `fiction-lab-engine.js` 验证来源、位置邻接、物品生命周期、二十刻时限与固定悬锤触发，计算中断点；在内存副本中应用。
3. 第二次模型调用检查意图与状态是否一致并生成正文；失败不提交。成功后由共用服务原子保存新状态与幂等回执。

每个物体具有稳定身份、普通物性、位置、完整/破损/消耗生命周期，以及可更新的自然语言事实。湿度、系结、遮挡等不需要各写一套字段与动作映射。模型可以裁定新用途，程序仅限定少量硬边界；语义和普通物理仍依赖模型，结构校验不能证明一切因果正确。

没有无限地图、NPC 和奖励生成。只开放石门外、门内近处、伪王墓三处相邻位置，以便验证连续行动、远处作用和跨轮后果。

## API 与存档

`/api/fiction-lab` 与原接口使用同一 D1 表结构、预算和锁机制，另用 `koa_fiction_lab` Cookie，路径仅覆盖新接口。状态含 `gameKind:lab`，Cookie 即使被交换也不能误读另一版的存档。无数据库迁移或旧存档重写。

两个模式分别限流，每 IP 每模式每天五个新局、一百次请求、每分钟十次行动；模型预算共用。原版未标 gameKind 的历史存档视为 classic。

每次完成需两次模型调用，GPT-5.6 Sol / low reasoning，输出上限分别3600、2200tokens；试玩每次调用45秒超时（原版维持30秒）。正文目标约360—440汉字，实际生成长度可能浮动。技术失败保留输入、进度不变，可重新提交；不假装游戏内失败，也不自动无限重试。预算用尽时新试玩暂停（包括建议按钮），原版仍保留规则叙事。

连贯行动可能在故事中部分完成，但落库要么整体提交已确认部分，要么完全不提交。发生悬锤等意外时，后续步骤中止。短准备可以零刻，整轮有物理变化至少一刻；真正澄清可以零刻。长期等待截断于剩余灯火，未完成的变化不应用。

## 验证

Node22：`node --test tests/fiction*.test.mjs`，运行现有回归与新的状态/服务测试。

测试包括连贯准备和投物、自然语言状态持续、失败依赖与部分完成、长时间截断、闭门边界、来源消耗与禁止复活、悬锤只触发一次、复核失败不提交、重试幂等、双存档隔离与预算拒绝。真实模型案例与封存盲测另行记录；自动测试通过不等于语义裁定绝对可靠。

## 发布与回退

GitHub main → Cloudflare Pages，沿用已有生产 DB 与模型绑定。回退本功能提交并推送即可恢复页面与代码；数据库无需删除。仅停止模型调用可将共用 FICTION_DAILY_BUDGET_USD 设0，但会同时影响原版的AI描写。不能把该等价预算说成转发商实际账单。

实验结果确定前不向原版迁移新裁定，也不为更多剧本复制细碎物理字段。下一步以真实试玩暴露的跨轮矛盾和意图偏离来评估核心，而非不断补齐关键词。
