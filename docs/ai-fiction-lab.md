# 门后的火光 · 主持裁定试玩

入口：https://koa-ol.com/games/lantern-tomb-lab/ 。本次试玩使用规则 v3，旧试玩存档按兼容规则读取；原《蛇墓余火》继续使用原规则。

## 目标与架构

解决玩家自由输入被动作白名单拒绝、复合动作被拆回按钮、点火被偷偷改成观察的问题。

1. `fiction-lab-host.js` 根据世界、玩家原话及近期事件提出局部步骤与变化。每轮最多六步，连贯准备、操作、观察可以在一轮完成。
2. `fiction-lab-engine.js` 验证来源、位置邻接、物品生命周期、连续动作暂停与固定悬锤触发，计算中断点；在内存副本中应用。
3. 第二次模型调用检查意图与状态是否一致并生成正文；失败不提交。成功后由共用服务原子保存新状态与幂等回执。

每个物体具有稳定身份、普通物性、位置、完整/破损/消耗生命周期，以及可更新的自然语言事实。湿度、系结、遮挡等不需要各写一套字段与动作映射。模型可以裁定新用途，程序仅限定少量硬边界；语义和普通物理仍依赖模型，结构校验不能证明一切因果正确。

没有无限地图、NPC 和奖励生成。只开放石门外、门内近处、伪王墓三处相邻位置，以便验证连续行动、远处作用和跨轮后果。

## API 与存档

`/api/fiction-lab` 与原接口使用同一 D1 表结构、预算和锁机制，另用 `koa_fiction_lab` Cookie，路径仅覆盖新接口。状态含 `gameKind:lab`，Cookie 即使被交换也不能误读另一版的存档。无数据库表结构迁移。v2 状态读取时转换为 v3，下一次成功行动才写回；仅因旧期限结束的存档恢复可玩，消耗物品和主动离开的结局保留。

两个模式分别限流，每 IP 每模式每天五个新局、一百次请求、每分钟十次行动；模型预算共用。原版未标 gameKind 的历史存档视为 classic。

正常完成需两次模型调用，矛盾结果最多额外纠正一次（最多四次），GPT-5.6 Sol / low reasoning，输出上限分别4200、2200tokens；试玩每次调用最多45秒，裁定整体截止90秒，预算预留耗时也纳入截止（原版维持30秒）。正文目标约300—440汉字，实际生成长度可能浮动。技术失败保留输入、进度不变，可重新提交；不假装游戏内失败，也不自动无限重试。预算用尽时新试玩暂停（包括建议按钮），原版仍保留规则叙事。

连贯行动可能在故事中部分完成，但落库要么整体提交已确认部分，要么完全不提交。发生悬锤等意外时，后续步骤中止。没有统一时间、灯油或世界轮数限制。段数仅作记录索引。持续变化基于实际行动或明确等待；暂停与纯确认不额外推进事件。普通连续动作的用途或风险发生实质变化时保存待决定事项，由玩家继续或取消。

## 验证

Node22：`node --test tests/fiction*.test.mjs`，运行现有回归与新的状态/服务测试。

测试包括连贯准备和投物、自然语言状态持续、失败依赖与部分完成、无回合上限、旧存档迁移、追问保留原始意图与决定接续、闭门边界、来源消耗与禁止复活、悬锤只触发一次、复核失败不提交、重试幂等、双存档隔离与预算拒绝。真实模型案例与封存盲测另行记录；自动测试通过不等于语义裁定绝对可靠。

## 发布与回退

GitHub main → Cloudflare Pages，沿用已有生产 DB 与模型绑定。回退本功能提交并推送即可恢复页面与代码；数据库无需删除。仅停止模型调用可将共用 FICTION_DAILY_BUDGET_USD 设0，但会同时影响原版的AI描写。不能把该等价预算说成转发商实际账单。

实验结果确定前不向原版迁移新裁定，也不为更多剧本复制细碎物理字段。下一步以真实试玩暴露的跨轮矛盾和意图偏离来评估核心，而非不断补齐关键词。

## 初版验收历史（2026-09-19，以下不是当前规则）

- 41项规则/API回归通过；真实Sol复现玩家三种原句及连续后续，共六轮均有有效回应，覆盖远处投布、条件开罩、点火取暖、接水熄火再试燃、仅系绳而不投拉。
- 在读取独立审查员封存案例前记录四个核心文件SHA256。首轮八例、每例连续两输入：15/16输入成功返回，一次模型30秒超时未提交；七个完整案例达到封存最低线，另一例未完成。不能把HTTP200或这次小样本等同于全面可靠。
- 审查发现并修复“同一步释放支撑与移动”导致的机关时序错误。首次修后B07重测虽然返回200，但主持擅自入门，审查判定失败；没有把失败当成通过。
- 随后明确已有场景几何：门槛边和门外石镇触手可及，门内两步落点是另一位置；不得替玩家跨区域。复测B03/B07共四输入，全部成功，角色全程在门外，纸片来源、记录和落锤后状态能恢复。以上为修订后复测，不计作新的首次盲测。
- 主持与复核仍是概率判断。首轮成功输入耗时约23—39秒，中位约30秒；正文233—396字符，中位348。对复杂步骤将新试玩的单次模型超时放宽到45秒，旧版保留30秒。
- Chrome检查1440/768/390px下开局、刷新、手记标签、资源和横向溢出，均通过。公开部署后再检查实际API与浏览器恢复。

真实测试记录、冻结摘要与独立审查报告留在本地任务产物目录，不向公开站点上传原始模型调用日志。当前证据支持隔离试玩，不支持把整座旧地城立即切换到该核心。

独立最终复核：准许修订候选上线隔离试玩。B03/B07修订后分别8/8分，输入未改写、恢复一致；机关时序与擅自入门两项阻断已关闭。半分钟等待与更长链条的事实稳定性仍待实际试玩观察。

## v2 持续过程与内部修正历史（已由 v3 取消计时）

本轮落实用户已同意的持续变化、一次内部修正、正文结构三项。背包容器与普通动作顺序的中断策略保持现状；后者继续讨论，不擅自改为失败后投掷。

- 提案增加evolution：按程序实际经过的刻数，给出已有物品的自然变化与原因。与主动作用范围分离，允许场外燃烧继续；不能由此生成或移动物体、修复损坏、复活消耗品或改关键机关。零耗时不能演化。事实附updatedAt只作时间依据，重复确认不因此多扣时间。
- knownEntities保存上次所见，物品消耗保留lastPlace；真实世界变化与公开投影分开。关门后手记不会从标题、内容或条目消失泄露门后最新状态，重新看见才同步。旧存档延续先前已公开的知识。
- 结构或语义复核失败可携具体原因从原存档重裁一次，最终只提交一次；预算/网络错误不作语义重试。最多四次调用且共用90秒截止，超时结果不允许提交。诊断只记录请求ID、revision、阶段和分类码，不记录玩家原文或凭据。
- 正常正文继续以300—440字为目标，减少未变化场景的清单式播报；简单澄清或无法着手可更短。

验收：51项完整回归通过，独立审查运行其中23项并关闭deadline、公共投影与元数据误扣时间问题。真实模型完成湿布两步、燃烧/关门等待/开门观察三步；另在本地复用该真实结果作八刻等待测试，布最终无明火，保留焦黑脆裂残片。内部修正及仅一次提交用注入失败的API测试验证，未把这些mock结果称为真实模型成功。

## v3 无统一计时与决定接续

- 删除固定灯油期限和世界回合上限。运营预算与防滥用限流保留，不能将其称为世界内时间机制。
- 步骤 beat 区分 action/wait/confirmation；evolution.basis 必须与已执行步骤匹配。决定暂停或机关强制中断禁止额外演化。
- decision 必须明确 none/keep/replace/resolve/cancel。追问保留最初原话、目的与尚未执行的动作；真正续做或明确取消才清理旧决定。落锤中断保存未执行后续。
- 背包容器机制保持原样。已完成后果不回滚，取消后续不恢复已用材料。
- 49 项回归通过，独立审查通过。真实模型六轮覆盖点火投布、白垩失败暂停、追问保留原计划、短答续投、纯确认不变和明确失败也投掷；均返回 200，另核对存档中的物品与 pendingDecision。Chrome 1440/768/390px 开局、恢复、资源和无横向溢出通过。生产浏览器验收见本次独立产物目录；旧章节的 41/51 项数量对应历史版本。
- 开局、每轮输入/输出、状态与记忆分层详见 [Context Engineering 实例说明](./ai-fiction-context.md)。
