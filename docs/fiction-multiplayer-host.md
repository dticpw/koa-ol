# 多人主持 v2：协调与长程记忆

本文保留 v2 发布时的设计记录；v3 的适配、休局恢复、事件存储与回退边界见 [多人主持 v3](fiction-multiplayer-v3.md)。

## 发布边界

本次先完善同场合作，不开放分队、私人频道、秘密传递或完整 D&D 战斗。详情页、行动区、新局开场与每轮上下文都明确“跨地点全队同行”；即使双方同意，也不承诺本版不能执行的分头深入。隔门观察、递物或投掷仍按距离与物性裁定，不误当分队。模拟玩家也读取这份公开模式说明。房主只控制开局/推进，所有角色仍由本人声明行动。旧局固定使用 v1；新局默认 v2。`FICTION_MULTIPLAYER_HOST_REVISION=cooperative-v1` 可将之后开局切回旧主持；已有 v2 局继续使用 v2，不能通过删掉新模块或把新存档交给旧解释器来回退。

没有数据库表结构迁移：新状态字段放在现有 state_json，原单人系统不变。部署前的旧多人状态没有 hostRevision，明确按 v1 解释。`host-v1.js`、`story-v1.js` 和 `discretion-v1.js` 保留上线时的协议、规则和场景。裁量正文单独冻结，之后修改单人主持的共享文件不会改变这些多人存档的行为。无法识别的版本保留存档并拒绝执行，不猜测格式。正式发布后若整体替换主持规则、剧本运行约束或记忆协议，应新增 revision 与对应实现，不继续覆盖 v2 却声称旧局被冻结。版本固定的是本地规则与协议，外部模型输出仍不是逐字确定的。

## 文件与每轮流程

- `host.js`：版本入口；创建新局、根据存档固定版本路由。
- `host-v2.js`：结构化裁定、程序验证、独立复核、最终正文与提交候选。沿用服务层原子提交、互斥锁和幂等回执。
- `coordination.js`：检查每位玩家的移动授权及限定场景跟随约定；hold 优先，当前撤销优先。
- `memory.js`：记忆更新、原始事件关联与来源核对、场景摘要和关注记录；不把聊天、摘要或别人发言当本人授权。
- `context.js`：场景相关资料、活跃承诺/计划/未完成行动、人物所知、最近交流及旧原文检索。
- `rules.js`：共同遵守的主持与复核规则，包含求助、合并动作、协作、卡关帮助和顺路收尾。
- `scripts/eval-multiplayer-host.mjs`：隔离 SQLite 的真实模型试玩；玩家模拟器只读公开正文及随身物品，评分另开无实现版本信息的模型调用。

一次推进：收齐本人声明 → 组装上下文 → 模型给结构化结果 → 程序检查 → 另一次模型复核并写正文 → 全部通过才提交新状态。裁定阶段不重复生成整段正文。两次模型输出都是尚未提交的候选。复核可依据原始世界与本人声明，通过corrections修正草案字段（null保留；非null完整替换该字段），然后写与最终候选一致的正文。程序重新检查所有修订字段，包括路线、hold、身份、归属、证据和记忆授权；只有最终候选通过才交服务层提交。这避免把可修正的记忆归属或普通细节分歧都变成多次整轮重跑。模型仍可能误判语义；程序约束不等于自动证明所有叙述正确。每份草案接受一次复核修正；总截止内至多再尝试一份草案。最终失败保留旧世界和玩家声明。实际模型调用使用原 callModel 及日额度；v2 整轮上限 150 秒、单次上限 75 秒，房间锁 180 秒、浏览器等待 165 秒。共享调用器新增显式超时上限参数，单人和 v1 不传该参数，仍保持原有 60 秒上限。

## 上下文的结构

`readingGuide` 解释字段用途与优先级。`scenario` 提供开场、当前位置/相邻场景及明确请求的短路线沿途细节、全图路线索引与必须遵守的核心秘密；未探索远处房间的全部细节不固定塞入。`operatingFacts`补充原稿的门锁、巡逻、分散注意及低警戒下的可行性，`opportunities`补充附近场景的真实机会，避免上下文只有限制、主持反复造阻碍。这些仍是主持资料，不能直接向玩家泄露。复核另读全图短约束与机会。秘密仅用于主持裁定，不能进入公开叙述。

`world` 包含世界位置、警戒、真实目标进展、角色与物品。`commitmentLedger` 完整携带全部活跃 commitment、plan、pending、agreement，避免承诺被相关度裁剪。输入记忆省略重复的原始证据副本，保留引用及承诺/授权所需的 origin 原话。完整证据仍在存档。`relevantMemory` 从其他记忆中按当前位置、相邻地点及本轮行动关键词选取最多 32 条，显式报告遗漏数量。`knownBy` 表示条目被哪些角色获知；[] 为主持知识。本阶段正文仍全桌共享，并不意味着已经有私人消息功能。

`sceneSummaries` 为当前/相邻已访问场景的摘要。`recentEvents` 保留最近 6 次结构化结果，`recentConversation` 为最近 12 条公开消息。`recalledHistory` 按当前输入的关键词、中文二元词及明确轮次查找旧原文，最多附 8 条；这是一种确定性的相关片段检索，不是保证穷尽的搜索，也没有让 LLM 任意查询数据库的工具。完整正文与不可变的 journal 仍存于本局，摘要不取代原文。

`spotlight` 记录各人最后获得具体回应的轮次；用于提醒主持关注，不控制行动权。chat 始终只是讨论，actions 才是这一轮的正式声明。

## 记忆与授权

条目区分事实、线索、人物关系、承诺、计划、未完成行动和持续跟随约定。模型为每条记忆提供 ID、最新状态、范围、相关人、获知人以及 evidence 事件引用（轮次、行动/结果类型、玩家ID）。程序关联真实原文形成 source，合并发现可引用多段结果，不要求模型重复抄录引文。第一次来源 origin 保留；状态改变留最近证据，完整改变依据仍在 journal 与原文。

持续跟随必须来自本人明确的阶段性安排，限定具体地点；一次“跟上”不能扩大成永久授权。程序直接从本人已认证行动或约定关联原话并核对范围，模型不用复抄引文；复核继续检查其语义是否真的授权，basis标签本身不是同意的证据。已获许可的普通赶路可连续经过最多三段相邻道路，程序逐段检查连接及跟随范围；首轮按路网拟路线，复核另读本剧本24个节点的短约束（不是原书全文），再检查门锁、警卫等前提；不要求玩家每轮准确重述地点名称。当前玩家拒绝、hold 或遇到新危险时停下，不按老约定自动消耗重要物品或替他交易。离开授权区域后约定失效。

计划/承诺标记 resolved 必须引用本轮真实 outcome，不能仅凭“我准备去做”记为完成。中断动作写 pending；再继续时结合当前意愿与局势，而非自动执行旧计划。低风险顺路收尾在已有明确授权、仍可行时自然结算。模型仍可能误解语义，结构校验与复核降低风险，但不构成完美主持保证。

存档容量保护不等于剧情倒计时：记忆最多 600 条，物品最多 120 件，序列化状态上限 1.5 MB。达到容量时保留现状并提示保存，不伪装成剧情失败。

## 验证与恢复

新增回归测试覆盖：主持版本隔离、聊天/他人不能伪造约定、持续跟随有效/超范围/撤销、hold 优先、承诺真实兑现、60 轮后旧承诺与原话检索、摘要不能授权、失败不污染存档、事件原档保留。

完整真实试玩、首次超时与迭代证据保存在 `/mnt/e/PG/koa-ai-fiction-resources/records/multiplayer-host-20260922/`。测试玩家及评分都由模型模拟，是诊断材料，不冒充真人体验结论。是否完成、分数与关键缺陷以实际记录为准，不由测试脚本跑到轮数上限推断通关。
