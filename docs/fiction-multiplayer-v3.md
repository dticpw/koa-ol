# 多人主持 v3：场景边界与跨晚续团

实现基于 v2 基础设施作局部重构，保留认证身份、本人声明、事务锁、请求回执与固定版本路由。当前仍为同场合作；没有上线跨房间分队、私人频道、完整 D&D 战斗或真人五人体验的保证。

## 版本与剧本适配

`host.js` 按存档的 hostRevision 路由到互相保留的 v1/v2/v3 实现。`stories/registry.js` 根据主持/剧本版本读取对应资料，旧局的地点显示也使用旧资料。v3 的进度 schema、初始物品、NPC动机、原稿条款和目标校验放在 `stories/prisoner-13-v3.js`；主持核心不再内置 keyCopied 与特定房间的目标校验。现有大厅仍只发布13号囚犯，尚非任意多人剧本通用大厅。

`v3/scenes.js` 定义场景、参与者、位置、可见记录和交接接口。生产一次结算仍等待同桌所有人。五人双场景的本地模块探针检查各自参与者、信息范围、唯一物品交接及汇合；它不代表已完成分队 HTTP 调度或真实模型五人验收。

## 每轮主持资料

1. 原稿资料：路线、普通门与反魔法牢门的区别、附近机会、NPC目标与可变通范围。v3额外保留13号本人通常参加日常放风/杂务的原稿机会，不能无依据删去整日安排而制造新审批；恶劣天气等已发生原因仍可限制庭院。
2. 本场真实状态：参与者、场景、进度、物品归属；跨场景模型工作资料与网页记录均有过滤接口。
3. `sceneBrief`：依据原记录临时生成的工作摘要，包括当前目标、最近尝试、机会来源、连续受阻者；可重建，不能升级成新世界规则。
4. 活跃承诺、计划、未完成行动及限定跟随约定；其他记忆按位置/关键词筛选。记忆区分 `event` 已裁定结果、`claim` 人物说法、`inference` 推测。引用只能证明来源存在，不能证明旧模型裁定符合原稿。
5. 最近12条交流、最近6次结算、最多8条旧原文。检索在关键词之外使用少量剧本别称和活跃承诺的来源轮次，仍非语义搜索，不保证召回全部相关信息。
6. 本人认证行动与仅供参考的队内讨论。

裁定与复核保持两次串行模型调用，不再无条件添加第三个导演。复核可修正整个候选，再通过程序验证提交。提示词强调兑现已有许可、普通连续行程可合并、失败应承接可行部分、有依据的帮助、自然完成已答应的低风险收尾。主动演角色和闲聊不是卡关，不以机械轮数处罚。

关注记录不再把 blocked 视为实质推进；连续受阻会进入摘要。是否给出合理帮助与通融，仍需实际文本审阅，指标不自动替主持做决定。

## 休局、离桌与恢复

房主可给未完的冒险命名并“休局并保存”，释放桌位。原参与者的大厅显示“未完的冒险”，任选无人空桌恢复；先回来的人暂任房主，原队员全部返回后才能继续。其他玩家看不到或恢复不了这份存档。同一冒险不能同时恢复到两张桌。

普通离桌会暂停未完冒险；最后一位离桌时自动保存。休局/离桌清空尚未执行的声明，回来后重新确认行动。结束并清桌保留历史归档，但不将已结束冒险伪装成待续局。

身份 Cookie 随有效访问滚动续期30天。仍没有跨浏览器账号或恢复凭证：超过有效期未访问、清除 Cookie、更换浏览器后暂不能找回原角色。不能以显示姓名替代身份认证。

休局、座位更新、存档恢复、事件写入与桌状态通过同一数据库事务及锁所有权保护；失败时全部回滚。修改锁过期后的候选不能留下部分座位或存档副作用。

## 长记录存储与现实边界

v3 的完整正文和结构化事件写入追加事件表；状态仅保留最近12条正文、6次结算及已写入游标。每次仅写新增事件，不重复全历史。浏览器首次读取最近40条，后续轮询只取新条目，可翻更早记录，导出时显式取全篇。可见范围先在查询端过滤，随后分页。

结算前仍会把完整历史从数据库载入，用于查找证据与检索；这不是无限长故事的方案。记忆仍有600条、物品120件、热状态1.5MB上限。容量保护是技术边界，不是剧情倒计时。后续应以实际百轮读写、上下文大小与延迟数据决定索引召回/压缩方式，不先引入向量数据库。

## 回退

上线通过新的 cooperative-v3 新局默认值。保留 v1/v2/v3 解释器。回退应把后续新局默认值改回 cooperative-v2；已经建立的 v3 局继续由 v3 读取，不能回滚到不认识 v3 或事件表的整包旧部署。

通用 `fiction_release.py rollback --apply` 不接受只验证了单人存档的报告来删除多人解释器；涉及多人内核的整体回退会被阻止，按版本路由回退。

数据库变化仅新增事件、休局保存、保存参与者和事务 guard 表，不删除旧表、不改写游客原存档。源码基线标签 `fiction-multiplayer-before-v3-20260922` 指向2529d56。源码包不是生产数据库备份；当前没有已验证的生产D1导出备份。

## 验证证据

自动化覆盖版本保持、休局恢复权限、竞态恢复、事务失败回滚、身份续期、45轮136条正文分页、旧引用跨裁剪恢复、增量写入、五人两场景接口。浏览器覆盖1440px/390px的完整休局恢复、导出、分页与无横向溢出。

模型对照与连续游玩记录位于项目资源库 `records/multiplayer-v3-20260922/`；最终是否通过、具体轮数、失败与局限以其中 REPORT.md 为准，测试停止不等于故事完结。v2既有44/36轮记录包含开发中迭代，不充当这次冻结对照。

候选A在真实游玩中误删原稿的日常放风机会，停止并保留失败记录。补齐资料后的候选B冻结运行23轮自然结束：玩家实际复制符文、撤离、归还首轮所借铅笔；两次上游503保留进度后续跑。成功主持等待中位67.09秒、最慢106.546秒，每轮两次模型调用。v2/v3各16次定点均通过，这些结果不证明新版整体优胜或速度提升。长局仍有通行过渡重复、风险偏宽松的观察；无人提醒时自动兑现承诺及真人五人体验未获本轮证明。

发布前167项Node回归、6项Python恢复测试及Functions构建通过。新局默认v3，旧版本测试显式指定对应解释器，避免默认切换掩盖旧局回归。
